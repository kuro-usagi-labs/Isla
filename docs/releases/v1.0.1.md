# Isla 1.0.1 — Playback stability

This patch moves avoidable work out of the audio render path and keeps playback
transitions advancing while controls are being adjusted.

## Improvements and fixes

- File reads and decoding run on a separate worker with a bounded PCM read-ahead
  buffer of approximately 250 ms. The output callback consumes prepared samples.
- Packet conversion buffers are reused, removing repeated allocations and an
  extra PCM copy during decoding.
- EQ coefficients and headroom are prepared on the control thread for each
  stream's sample rate. Live changes retain the existing smooth bank crossfade.
- Continuous EQ/volume commands no longer postpone crossfade/progress ticks.
- Upcoming-queue calculations are reused during playback progress updates.
- The Settings version label now follows the package version.

## Validation

39 native tests and 55 frontend tests passed locally on Windows. TypeScript and
the production build passed. MP3, FLAC, WAV (96 kHz) and M4A decode paths were
exercised with two decks, live EQ and CPU load.

A 60-second timed Windows output probe recorded a maximum callback work time of
0.6118 ms against a 10 ms minimum work budget, with no work-budget overruns,
decoder-buffer starvation or reported stream errors in that probe.

See the [full audit and limitations](https://github.com/kuro-usagi-labs/Isla/blob/main/docs/performance/2026-11-12-playback.md).
These bounded measurements do not guarantee interruption-free playback on every
device/driver or during long sessions, and do not measure late callback starts.

## Downloads

- **Windows x64:** `Isla_1.0.1_x64-setup.exe` — NSIS installer; WebView2 required.
- **macOS Apple Silicon:** `Isla_1.0.1_aarch64.dmg`.
- **macOS Intel:** `Isla_1.0.1_x64.dmg`.
- **Linux x64:** `Isla_1.0.1_amd64.deb` or `Isla_1.0.1_amd64.AppImage`.
- **SHA256SUMS.txt:** checksums for the five installers above.

Windows is the primary tested platform. macOS and Linux remain experimental;
native compilation and automated checks do not replace hands-on audio/desktop
integration testing. Transparency, click-through, shortcuts and output routing
depend on the platform/window manager. Startup integration is Windows-only.
The Windows installer is unsigned; macOS builds are ad-hoc signed, not notarized.
